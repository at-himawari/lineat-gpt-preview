# テストガイド

## 概要

このプロジェクトでは、購入導線とカウントロジックの品質を保証するために、包括的なテストスイートを実装しています。

## テストの種類

### 1. 単体テスト

各サービスとハンドラーの個別機能をテストします。

- **カウントロジックテスト** (`database.test.js`, `database-reset.test.js`, `database-quota.test.js`)

  - プレミアムユーザーの 100 件制限
  - 非プレミアムユーザーの 30 件制限
  - 1 日経過後の自動リセット
  - 枠拡張時の処理

- **購入導線テスト** (`stripe.test.js`, `stripe-webhook.test.js`)
  - Checkout セッション作成
  - Webhook 処理
  - 商品タイプ別の処理分岐
  - エラーハンドリング

### 2. プロパティベーステスト

fast-check ライブラリを使用して、多数のランダム入力で正確性プロパティを検証します（最低 100 回の反復）。

## テストの実行

```bash
# すべてのテストを実行
npm test

# ウォッチモードで実行
npm run test:watch

# カバレッジレポート付きで実行
npm run test:coverage

# 単体テストのみ実行
npm run test:unit

# 統合テストのみ実行
npm run test:integration
```

## CI/CD

GitHub Actions を使用して、プルリクエストと main ブランチへのプッシュ時に自動的にテストを実行します。

### ワークフロー

- **テスト実行**: Node.js 18.x と 20.x でテストを実行
- **カバレッジレポート**: Codecov にアップロード
- **テスト結果のアーカイブ**: 失敗時の調査用

## テストの追加

新しい機能を追加する際は、以下のガイドラインに従ってテストを作成してください：

1. **単体テスト**: 各関数の基本動作をテスト
2. **エッジケース**: 境界値や特殊なケースをテスト
3. **エラーハンドリング**: エラー時の動作をテスト
4. **統合テスト**: 複数のコンポーネントを組み合わせたフローをテスト

## モック

テストでは以下のモックを使用しています：

- **mysql2/promise**: データベース接続
- **stripe**: Stripe API
- **utils/logger**: ロガー

## トラブルシューティング

### テストが失敗する場合

1. 環境変数が正しく設定されているか確認
2. モックが正しく設定されているか確認
3. テストの実行順序に依存していないか確認

### カバレッジが低い場合

1. 未テストのコードパスを特定
2. エッジケースのテストを追加
3. エラーハンドリングのテストを追加
